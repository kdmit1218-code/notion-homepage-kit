# 项目页与决策格式

已有页沿用合适的结构，新页采用以下模块，有内容才展开。

页首沿用或补充目录模块（原生 table_of_contents），正文用清晰标题；跨页面主题入口按 homepage 目录流程维护，不给每条决策重复建页。

## 项目概览

目标、当前状态、最新方案和真实产物链接。区分已完成、进行中与待验证。

## 决策日志

三级标题“日期｜议题”，正文为结论、理由（必要时含替代方案）、影响与下一步。日期使用当前会话与配置时区。简单决策可一段写完；比较方案时才用表格。

## 当前结论与变更摘要

摘要正文面向下次使用，只保留当前有效结论、必要理由、关键证据及下一步；过程细节和重复解释不逐轮追加。同主题优先重写对应章节。

已确认的新决策与旧方案冲突时，正文改为新方案，旧方案压缩为“日期｜旧→新｜原因”一条；必要时关联原始来源。比如“待发布→GitHub 已发布；完成审核上传”，正文状态只显示已发布。尚未接受的建议或未解决的冲突保留为待决定，不按最后一句话覆盖。

这是维护摘要的默认规则；原始资料、用户要求完整保留的审计日志、附件及子页仍按原约定保留。只改当前主题的已授权摘要，不清理无关历史资料。

## 可复用知识

按主题整理概念、方法、复现步骤、技术条件和来源。代码加语言标签；长细节放 toggle，关键结论保持可见。不逐条复制聊天、不填造负责人、测试通过或不存在的文件链接。

## 待办与待决定

只记录实际存在的事项，无期限不虚构。用户自己的想法、资料中的事实、助手推断分别表述；尚未同意的建议保留为待决定。
