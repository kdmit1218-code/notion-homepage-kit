# 项目开始、决策同步与恢复

## 定位项目

读取配置与实时主页。先查已核实 project_aliases，再搜索项目名及会话已有别名，核对正文与入口。默认以当前主页树和主页已链接项目为目标范围；其他可访问页面只有确实属于该用户此项目才纳入。多个候选难分时询问，不盲目使用最新编辑页。

已有当前项目页直接续写。同项目历史快照只是参考，不能因名称相近就在档案续写。一个聊天同时涉及多个项目时分别定位并分批写入，跨项目决定可互相 mention，不复制整个日志。

确认没有项目页且用户允许 auto_create_projects 时：在其 Homepage 下创建项目页；标题取真实项目名。使用 note-format 模板；随后补 Projects 入口。没有自动创建授权时询问或返回保存草稿。搜索失败/无权限不是空结果。

## 同步决策

1. 提炼本轮已确定的决定，分清“拟采用”“已决定”“已实施并验证”。
2. fetch 项目页及相关章节，按议题、结论与来源查重。已写入的同一决策不追加。
3. 更新当前状态，追加决定的日期、结论、理由、影响/下一步；出现取代关系时链接或说明旧决定。
4. 可复用知识放知识章节或子页；只将真实已授权的执行任务写待办，不自建额外任务系统。
5. 项目页创建或结构变更后 fetch；核对主页有项目 URL 且详情可达。

## 失败与幂等

建页成功但补入口失败：保存返回的项目 URL，重试仅补入口，不能再建页。超时结果不确定：先搜索与读取，确认是否已生效再重试。更新成功后回读失败：报告写工具成功但回读未验证，不能声称全流程验证。

重读发现他人或用户新编辑时按新正文计算最小修改，不使用旧全页覆盖。临时连接错误可进行一次有依据的重试；仍失败保留待同步摘要与目标 URL，继续独立项目工作。用户修复连接后先查重再补写。
