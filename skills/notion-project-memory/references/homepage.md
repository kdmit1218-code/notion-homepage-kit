# Homepage 模式与维护

这是去掉个人账号数据的布局方法，不是作者主页的复制品。当前用户主页经 fetch 后才是实际参考。用户可以改名字、章节、语言与分类。

## 新主页模板

标题由 properties 设置为配置中的 homepage_title，正文不要重复标题。读取 Notion Markdown 规范后，以这些语义区块创建：

- 顶部：显示名称及 Today · Current · Projects · Archive 导航说明。
- 目录：原生 table_of_contents 与已建主题入口，随实际标题和页面维护。
- To-do / Notes：两列 58% / 42%。首次可以用普通列表；只有实际工具支持且用户要求时创建数据库。不把“数据库待创建”说成已建立数据库。
- Current：正在推进的项目与状态，用原生页面 mention。
- Timeline：需要事件时建表或使用已有数据库；新主页不虚构同步块引用。
- Learning：学习主题、当前进度与真实资料链接。
- Projects：项目卡片，项目名、一句话用途和原生 mention；三列宽度 33% / 33% / 34%，分类名称由使用者决定。项目少时列表即可。
- Quick Access：Inbox、知识索引、Archive 等实际已创建的页面入口。
- Recently Completed：用户确认完成的项目与真实完成日期。
- Library / Reference：折叠长资料入口；保留可见的主要项目导航。

模板是首次建页的选择，不要求把已有主页强制改造成这个布局。没有内容的章节可留一句用途说明，不生成虚构项目、进度或日期。

## 自动维护范围

新增项目后检查 Projects 是否已有该 URL；补一个入口即可。决策内容留在项目页。必要时更新该项目一句状态，不每次重排全主页。已有分类可匹配时使用对应卡片；新类别放在 Projects 中新增简洁分组，保留原分栏。

用户明确要求主页整理时：先 fetch 完整目标，列出实际重复、失效和缺失入口，在指定范围内修正。无法读取的链接标为权限待核实，不删除。不得用全文替换去掉未识别的块或子页。

## 目录模块与主题归属

每次保存前检查主页现有目录、分类入口和目标页：按主题含义、别名、正文与页面 URL 判断归属，不只看标题是否相同。同主题的新结论补到已有页或章节；确实独立的新主题才按授权建页。多个候选有实质歧义时询问；暂无法归类的已授权内容放现有 Inbox 并保留目录入口，不随意新建分类。

本次维护的主页及内容页必须具备目录模块。已有模块直接沿用；缺失时以最小插入补充“目录”和原生 `<table_of_contents/>`，新内容使用有意义的标题，使页内目录能显示。原生目录只索引当前页标题，不包含全部子页：主页还需用原生 mention 维护主题索引，沿用 Learning、Projects、日程等真实分类；已有索引页就复用并从主页链接，不为每次写入建一个索引页。

目录排版保持简洁：短标题、按真实分类分组，每项只显示主题名、必要状态与一个入口，说明最多一句话。少量分类可用两列浅色 callout；窄屏或条目少用列表。不在目录展示操作日志、完整决策或重复摘要。原生页内目录过长时放进“展开章节”折叠块；先收敛正文标题，不靠装饰掩盖重复内容。色彩与图标沿用主页风格，避免新增封面和大块空白。

旧主题更新不增加重复入口；新页面或新子主题补所属目录的唯一入口，新章节由页内目录展示。主题较多可分级索引，保持 Homepage → 分类/主题索引 → 内容页可达。跨分类用关联引用，主要正文只维护一份。用户另有目录约定时遵循。

写入后核对标题、页内目录模块及主题入口；新建或结构修改后回读验证。正文成功而目录失败时报告部分完成，并只补目录。维护范围是本次目标与导航链，不擅自扫描改写全部历史页面。

## 完成与归档

仅在用户确认项目完成或要求归档时更新对应状态。从 Current 移除入口前保留 Projects/Archive 或 Recently Completed 的入口。默认归档是导航和状态变更；移动页面、删除数据库记录或改变共享权限需要相应明确指示。用户要求恢复时恢复当前入口，保留历史。

## 可找到的定义

Homepage 有目录模块与分类主题入口；项目详情、决策和子知识页沿目录导航链进入。搜索依赖有意义的页面标题、项目别名与清晰章节；不承诺 Notion 的索引刷新时间或任意全文搜索结果。主题较多时复用单独索引并从 Homepage 链接，避免无限增加主页卡片。
