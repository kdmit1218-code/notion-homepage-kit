# 项目总结与历史补录

用于当前项目总结，或用户指定的历史聊天、项目资料补录。日常决策记录继续按 project-workflow 流程执行，不自动扫描所有账号聊天。

## 提供一次整理机会

首次接入已有项目且明显缺少历史记录，或用户要求阶段总结、收尾和补录时，可提供“整理当前聊天 / 整理选定历史聊天或项目资料 / 以后再整理”的入口。同一项目不要每轮重复提示；用户跳过就继续原任务。当前请求已明确指定范围时直接处理，不再要求重复确认。

示例：“整理这个项目可读取的聊天和文档，按我的 Homepage 分类，输出项目进度、关键决策和可复用知识，查重后同步。”这只是用户选定范围内的执行入口，不代表已取得全账号历史访问能力。

## 先明确实际来源

可用来源包括当前可见聊天、用户提供的导出或粘贴记录、用户指定的项目目录与文档、已授权工具能读取的指定历史会话。核对真实工具和权限；Notion agent sessions 不是 ChatGPT/Codex 聊天历史。

没有历史工具时，先完成当前材料的整理，再说明尚缺哪些历史来源。聊天链接只有工具能读取时才能算已扫描；可让用户提供相关记录或导出文件，不要求为一份项目总结导出整个账号。已有本地会话日志可访问也不等于授权扫描全部用户目录；需用户指定项目/会话范围，先列标题、日期、路径等最低必要元数据再筛选正文，不读取凭据或无关项目。

## 整理与同步

1. 建立来源清单：标识或路径、可用日期、已读/未读/截断状态、对应项目。报告范围和缺口，不把部分资料称为全部历史。
2. 以项目名、路径、已有别名及正文核对归属。多个项目分开整理，难以归属的内容先列待分类，不硬塞入当前项目。
3. 提炼项目目标、当前进度、关键决策、完成证据、未解问题和下一步；区分用户确认、助手建议、工具结果。按日期梳理变更，已确认取代的旧方案压缩成简短变更记录，正文重写为当前方案；冲突未能解决时保留争议，不把最新提及等同最新生效。
4. 读取目标现有记录，按议题、结论、来源查重。可复用概念与方法按 knowledge 流程写 Learning，项目变化写 Projects，互相 mention。历史补录注明来源日期与本次整理时间，不伪装为今天新作的决定。
5. 按用户已有记录授权或此次明确的同步要求写入；只要求扫描/建议时先交付整理结果。新建/结构调整后回读对应页面和主页两类入口。

长资料按项目和时间分批，保存已处理来源、主题及待办清单。恢复时续处理未完成范围；不再次创建成功的页面。来源清单保留为项目补录记录或本地运行数据，不放入公开分发包，不默认存聊天全文。

交付说明读了哪些材料、形成了哪些项目/知识条目、哪些部分缺证据，以及真实 Notion 链接。未进行完整历史扫描时直说。
