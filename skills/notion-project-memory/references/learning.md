# 学习模式与知识沉淀

用户在本知识工作流中提出学习、理解、练习或复习时使用。只要求保存现成资料时直接按 [knowledge.md](knowledge.md) 整理，不强制先参加练习。普通项目任务继续执行；用户说“直接给答案”“先完成项目”时立即按其要求调整。

## 选择学习方式

- **讲解**：适合“帮我理解这个概念”。说明核心原理、适用条件，用当前项目的具体例子解释；有常见误区时说明。已知水平从当前对话推断，缺少必要背景时只问一个关键问题。
- **引导练习**：适合“带我学”“让我试试”。先明确本次能做成的事，再围绕一个关键点提问或给小练习。每次一个问题，依据回答给反馈和逐步提示；卡住时补解释，用户请求答案时给答案。可以让用户用自己的话复述，或将方法用于新的例子；不反复要求从零学起。
- **复习**：适合“复习上次内容”。先读取该主题已有笔记中的薄弱点，让用户尝试回忆或应用，再展示解释与纠正。没有旧笔记时说明，不编造历史成绩。

一次学习可在这些方式之间切换。不要求专门安装第三方导师技能；若用户已选择导师技能，由其指导学习，本技能只负责定位、整理与写入 Notion。

## 学习与记录的节奏

以一个概念讲清、一个练习完成、用户要求小结或话题结束作为整理节点。不要每轮问答创建页面。同一主题先搜索与回读已有页；继续更新主题页，关联当前项目与 Homepage 的 Learning 入口，遵循 [knowledge.md](knowledge.md) 的导航和数据库规则。

写入遵循用户已授权的范围：明确要求保存，或明确启用学习内容自动记录时，在节点同步；只启用 `on_decision` 的用户仍只自动保存已确定的项目决策与相关知识。仅开启学习模式不等于授权记录所有聊天。暂停记录时保留聊天小结，不写 Notion；已授权的节点无需重复询问。没有新知识或练习结果就不重复追加。

项目中需要记录的确定决策按原有规则及时保存，不等待整节课完成。学习日志与项目日志引用同一知识正文；由一个记录流程负责写入。

## 笔记保存什么

按本次实际内容选择字段，不填空模板：

- 学习目标和核心概念：回答什么问题、在哪些条件下成立。
- 方法与具体例子：如何使用，相关项目或产物的真实链接。
- 易错点：用户实际暴露的误解、对应纠正；没有观察到误解就不捏造。
- 练习证据：用户的简短回答或结果，以及是否需要提示。没练习时标“已讲解，尚未练习”；做对一个例子只描述该次表现，不宣布整体掌握。
- 下次复习问题：一到几个能检查回忆或迁移的问题，以及尚未解决的疑问。
- 来源与核实时间：材料链接、适用版本；来源事实、助手解释和未验证假设分开表述。

“内容已核实”和“用户能独立应用”是两个维度。用户说“懂了”可记录为自述，不当作练习成功。未经核实的解释保留为待核实内容，不因整理成笔记而变为事实；新证据纠正旧笔记时保留必要的变更说明。

长对话接近上下文边界时，先在已授权范围内保存阶段小结：目标、已有结论、当前薄弱点、未完成问题。下次从实际 Notion 记录继续，不声称能访问其他未提供的聊天。

## 项目实操与复习边界

优先使用短例子、独立练习片段或用户指定的练习文件。不要为了模仿学习模式而在需要交付的代码中留下未完成的 `TODO(human)`，除非用户明确选择这种实操方式。教学练习与项目完成状态分别报告。

可给出适合用户节奏的复习建议，但没有调度工具与用户授权时，不承诺主动提醒或后台复习。记录日期使用配置时区；无需为了复习改造整个主页或创建新数据库。
