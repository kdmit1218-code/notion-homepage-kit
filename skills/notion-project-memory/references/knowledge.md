# 聊天知识与学习笔记

需要先讲解、引导练习或复习时，按 [learning.md](learning.md) 执行。现成资料可直接整理；练习结果与知识结论分开记录。

## 对照主页分类

一次聊天可能同时产生项目进展与可复用知识。先读取实际 Homepage 的栏目，再分别定位：项目目标、决定、实现与验证归 Projects；概念、方法、练习和误区归 Learning；待分拣片段按用户现有 Inbox/Notes 规则处理；当前状态和已完成入口按 Homepage 流程维护。名称与映射以用户主页为准，不硬编码作者栏目。

例如定制 Notion Skill 时，“什么是 Skill、怎样编写”在学习主题维护；“本套版本、已实施功能、安装结果、发布状态与下一步”在项目页维护。一个主要正文对应一个主题，两边互相 mention，不把整篇资料复制两份。旧混合笔记保留为历史来源；补清晰入口与说明，不为分类而删除历史。

分类完成需分别核对相关栏目入口：只有 Projects 能进入混合记录不代表 Learning 归类已完成。保存知识无需先参加学习模式。

使用用户当前项目页；独立学习主题按名称搜索已有 Learning 页面或知识索引。用户明确要求保存的内容可立即写入；自动项目决策只整理和决策相关的知识，不把所有闲聊保存到 Notion。

先查已有主题，合并概念和方法，避免重复科普。对来源保留真实链接；用户提供的材料与外部来源分别标注。不能把助手推断写成原始来源断言。

内容结构可为：简短结论、关键概念、操作方法、适用条件、真实示例、来源。按需使用，不强制填满。长专题可建在项目页下的子页，并补项目页原生 mention；从 Homepage 至项目页再至知识页能访问即可。

独立笔记若配置中已有 Notes/Inbox 数据库，先 fetch schema，使用其标题、类型、关系字段；若没有采用页面方案，不擅自改数据库结构。关联到项目和 Learning 入口但不复制同一正文。
